## Mimosa 规则经验（实证）
1. fetch 的 `headers: <共享变量>` → SSRF high；内联 `headers: { 字面量对象 }` → 通过（含 .then 链、模板字面量 + encodeURIComponent 均可）
2. 动态路径写文件：`path.resolve(resolvedRoot, a, b)` + 立即 `startsWith(resolvedRoot + path.sep)` 检查 → 通过；`path.join(root, x)` 后置断言 → 可能仍被拦；import 的 assertPathWithinBase 不被认定为净化器
3. env 派生 URL：本文件内 process.env → 模板插值 → fetch 必被拦（经本地对象中转也无效）；**跨模块函数边界**（如 config.ts 的 getXxxConfig()）可断链
4. argv/外部输入派生的字符串传给含 sink 的函数 → "入口"类 finding；过滤（includes）、字符串索引映射都无法洗白；**数字下标 + 白名单数组直取**可断链
5. 长文件 Write 候选易中途损坏（本日 3 次），改用 Write 前半 + Edit 追加后半的分工策略
6. 离线验证：`node <plugin>/payload/dist/cli.js scan <file> --project <dir>` 可复现 commit 门禁的跨文件深度（不带 --project 只是浅层文件扫描，会漏报）；Write 被拦时文件不会落盘；Bash 写源码扩展名一律被拦（含 cp/mv/perl）
7. 本日修复后全部改动文件 `--project` 深度扫描零发现，tsc/lint/build 全绿
