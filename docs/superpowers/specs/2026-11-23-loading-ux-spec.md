# 加载体验规范（Phase 2）

> 角色：体验设计（ux-designer）
> 范围：只定义**加载期的行为与反馈**，不含图片管线实现、不改业务组件代码。
> 约束基线：无障碍不回退（横向溢出 0 / 无名可交互元素 0 / 触控热区 ≥44px）、不新增动画库、动效只用 `tailwind.config.ts` 与 `app/globals.css` 的既有 token。
> 关联产出：`lib/image-tiers.ts`（visual-architect）、`components/BookViewer.tsx` 预取（任务 #5）。

## 0. 一页结论（先看这个）

| 决策项 | 结论 |
|---|---|
| 预取窗口 | `+1`（P1，必做）、`-1`（P2）、`+2`（P3，仅空闲）。**不做 ±2 对称，不做全书预取。** |
| 预取触发 | **不在挂载瞬间**。当前页 `settled`（load/error）或挂载后 1500ms（取早）才发第一路。 |
| 并发上限 | **2**，且**当前页在飞时降为 1**（预取不许和屏幕上那一页抢带宽）。 |
| 预取重试 | **不重试**。失败只在用户翻到该页时由 P0 路径重新发起。 |
| 翻页时机 | **B「立即翻 + 占位填充」**。A「等图到位再翻」**否决，阈值 = 0ms，不等待**。 |
| 快速连翻 | 2s 内 ≥3 次落定 → `skimMode`：窗口收为 `{+1}`、并发 1、无扫光、无失败态、播报防抖。 |
| 弱网 | `saveData` / `2g` → 预取 0 路、档位 768 以下；`3g` → 预取 1 路、档位 768；iOS 无 `navigator.connection` → 用第 1 页实测吞吐回退判定。 |
| 加载反馈 | 0–300ms 无反馈、300ms 扫光、1200ms 文案、5s 慢网提示+重试、≤13s 失败态。 |
| 封面缩略图墙 | 6 格各显示 157–253px，**按格宽取 320/480 档，不按 DPR 升档**；骨架底恒在，**逐格独立淡入，绝不 all-or-nothing**；格内已有标题文字，**可点性不依赖图片**。 |
| 翻页预取（封面页） | 封面即预取**第 1 页的阅读档大图**（P1）——封面 → 场景页是必然的下一步。 |
| 首屏可用 | 分三级：**M1 封面可用 ≤1.5s**（文字可读 + 墙可点）、**M2 第 1 页可读 ≤1.8s**（文字 + 朗读）且插图 decoded **≤2.5s**、**M3 墙完整 ≤3.0s**（非门槛）。**不等全部 6 页。** |

**最重要的一句判断**：本轮「翻页空白」的**主因是编码，第二个主因是缩略图墙替阅读页垫付了全部字节**。

（一）**编码**。6 张 1024×768 PNG 实测 10.63MB（`public/generated/idiom/九牛一毛/`，单张 1.58–2.10MB，均值 1.77MB），换成 1024w WebP 约 110KB/张——4Mbps 下单张传输 ≈220ms，**已经短于移动端 slide 动画的 240ms**。

（二）**缩略图墙垫付**（lead 实测定位，本节据其修正）。那 9MB 不是「进阅读页预加载了 6 页」，而是封面页的缩略图网格（`BookViewer.tsx:974`，移动 2 列/≥sm 3 列，每格显示 **157px**）把 6 张 1024×768 原图全拉了。于是：
- 用户**还没开始读，就先为一个 157px 的缩略图墙付了 9–10MB**；
- 而「翻页不空白」是**假象**——图早就在内存里了，等墙改成小图，翻页就真的要从零下载 1.8MB。

**因此本规范的一个前提被 lead 修正并采纳：翻页预取不是「多余的优化」，而是当前缺失的必备能力。** 全文的预取设计与翻页裁决**都假设「邻页图尚未在内存中」**（我从一开始就是按这个前提设计的：`decodedCache` 从空开始、B0/B1 双路径、占位态全套）。但要修正一处措辞：格式修复让单页成本降到 220ms，**不是让预取变成兜底，而是让预取有了从容的余量**——没有预取时，4G 下翻页仍会看到 220ms 的占位（虽然恰好被 slide 的 240ms 遮住，是运气不是设计）；有预取时才是稳态。

## 1. 实测底数与推导

| 项 | 实测/推导值 | 来源 |
|---|---|---|
| 单张插图 | 1024×768 PNG，1.58–2.10MB，均值 1.77MB | `ls -la public/generated/idiom/九牛一毛/` |
| 单本 6 页合计 | **10,625,821 B ≈ 10.6MB** | 同上（逐张求和） |
| `book.json` | 10.5KB | 同上（**不含 base64 大图**，所以进阅读页后的主要成本是图片本体） |
| 4G 4Mbps/150ms 下单本 | 10.6MB ÷ 500KB/s ≈ **21.3s** | 与 lead 实测「15–20s 图空白期」吻合 |
| 换成 1024w WebP q80 | ≈110KB/张（水彩写意，估算区间 90–140KB） | 需 visual-architect 实测确认 |
| 换格式后单张传输 | 110KB ÷ 500KB/s ≈ **220ms**（+1 RTT ≈ 370ms） | 推导 |
| 阅读页插图显示宽度（移动 390） | 卡宽 366px（`max-w-[560px]` 内 `px-3`），图区 366×274.5 | 由 `BookViewer.renderSceneSingle` 布局换算；`max-h-[46dvh]`(388) 与 `min-h-[180px]` 均不触发 |
| 阅读页插图显示宽度（桌面） | stage `max-w-5xl`=1024 − 箭头 44×2 − gap → 904，半页 452，减 `p-6` → 图区 ≈404px | 由 `renderSceneSpread` + `PagerArrow` 换算 |
| **封面缩略图格宽（移动）** | 卡宽 366 − `p-5`×2(40) = 326，`grid-cols-2 gap-3` → 格 **(326−12)/2 = 157px** | `BookViewer.tsx:974–1005`；与 lead 实测的 157px 一致 |
| **封面缩略图格宽（≥sm / ≥md）** | sm 3 列 → 约 168–184px；≥1024 视口受 `md:max-w-none`+`md:p-8` 影响 → 约 **253px**（1440 与 1024 相同，stage 被 `max-w-5xl` 夹住） | 同上，逐断点换算 |
| 书架卡封面显示宽度 | 294–358px | lead 实测 |
| 缩略图墙换档后总字节 | 移动 6 格 × 320w ≈**84KB**；桌面 6 格 × 480w ≈**150KB** | 估算，待 visual-architect 实测；对比现状 9–10.6MB |

**由此得出的四条硬约束**（写进规范，不允许在实现时被"优化"掉）：

1. **阅读页只出两档：1024（默认）/ 768（弱网）**。1024 与现有 PNG 同像素，**零画质回退**；DPR3 移动端需求是 1098，不出 1152 档（多 25% 字节换不可辨锐度）。
2. **缩略图墙只出 320 / 480，按格宽取档，不按 DPR**（详见 §3.6.1）。这是全站唯一一处放弃 DPR 对齐的展示位——把它"统一"回 DPR 公式会 6 倍放大成本且无功能回归可测（§11 R11）。
3. **URL 必须由同一个纯函数产出**（`lib/image-tiers.ts` 的 `pickImageTier()`），`<img>` 与预取器都调它。预取器**禁止**自己拼路径——预取的 URL 与渲染的 URL 不一致 = 双倍下载 + 画质跳变，这是本轮最容易踩且最难测的坑。（**lead 已上升为全局硬规则**，落点见 §3.7）
4. **会话内档位只降不升**。进入阅读后若判定为弱网而取 768，本次阅读期间不再回补 1024（回补 = 二次下载 + 可见的清晰度跳变，两个成本都换不到可感收益）。因此**本次不做「高清」开关**（lead 已裁决）；若产品后续要，需重新定义重载语义。

## 2. 会话质量档（所有策略的分岔点）

在 `BookViewer` 挂载时算一次，存 ref（`qualityRef`），**本次阅读期间只降不升**。

```
quality = 'full' | 'reduced' | 'minimal'
```

| 输入条件 | quality | 阅读档位 | 预取并发 | 预取窗口 |
|---|---|---|---|---|
| `saveData === true` | `minimal` | 768 | **0** | 无 |
| `effectiveType === 'slow-2g' \| '2g'` | `minimal` | 768 | **0** | 无 |
| `effectiveType === '3g'` | `reduced` | 768 | **1** | `{+1, -1}`（严格串行，先 `+1` 后 `-1`） |
| `effectiveType === '4g'` | `full` | 1024 | **2** | `{+1, -1, +2}`（`+1 ∥ -1` 并行，`+2` 仅空闲） |
| 无 `navigator.connection`（**iOS Safari 全部版本**） | 先 `full`，实测后可能降 | 1024→768 | 按实测 | 按实测 |
| 实测弱网（见下） | `reduced` | 768 | 1 | `{+1, -1}`（串行） |

### 2.1 iOS 回退（必须实现，不是可选项）

`navigator.connection` 在 Safari / iOS 上**完全不存在**。iPad 陪读是本产品主力场景，所以必须有实测回退：

**第 1 页图片首字节到 decoded 的实测吞吐**（用 `PerformanceResourceTiming` 的 `transferSize / duration`，或用 `load` 事件时间 − `fetchStart`）：

- 若 `decoded 耗时 > 3000ms` **或** `估算吞吐 < 200kbps` → 判定为实测弱网，**在落地后的下一个 idle 窗口把 `quality` 降为 `reduced`**，并且：
  - 之后的新页用 768 档
  - 预取窗口收为 `{+1, -1}`（严格串行），并发 1
  - **已渲染的当前页不回补**（同"只降不升"）
- 判定只做一次（第 1 页那一发），避免"每页都重新评估"导致档位抖动。

### 2.2 change 事件

`navigator.connection.addEventListener('change')` → 重新计算，但**只允许降档**（`full→reduced→minimal` 单向）。升档一律忽略，理由同"只降不升"。

## 3. 产出 1：预取判定表

### 3.1 窗口与优先级

```
             ┌─────┬─────┬─────┬─────┬─────┬─────┐
             │ N-2 │ N-1 │  N  │ N+1 │ N+2 │ N+3 │
             └─────┴─────┴─────┴─────┴─────┴─────┘
   优先级       —    P2    P0    P1    P3     —
   触发时机          降档后 立即  P0后  空闲   —
```

- **P0 当前页**：屏幕上这一页，`<img fetchPriority="high" loading="eager">`，永远第一优先。
- **P1 下一页 `+1`**：唯一"必做"的预取。理由：阅读是前向的，TTS 自动推进是**严格前向**的，且 TTS 给了我们可预测的提前量（旁白时长）。
- **P2 上一页 `-1`**：儿童会回翻看"刚才那张"，但回翻是"我漏看了什么"的低频事件，容忍一点等待。排在 `+1` 之后；弱网（`reduced`）下严格串行在 `+1` 完成之后，不抢带宽。
- **P3 `+2`**：只在"前后都 settled 且浏览器空闲"时发。它是给"孩子连点两下下一页"兜底的，不是常规路径。

**方向优先级的裁决：前向优先。** 平局（`+1` 与 `-1` 同时可发但只剩一个槽）时给 `+1`。理由：TTS 自动推进严格前向（`startSceneReading` 的 `sceneIdx+2`），这是**唯一可预测**的翻页来源，给它提前量收益最高。

### 3.2 触发时机

| 场景 | 行为 | 理由 |
|---|---|---|
| 挂载瞬间（刚进阅读页） | **不发预取** | 此刻当前页本身还是空白，任何预取都在和"用户眼睁睁等的那张图"抢带宽 |
| 当前页 `settled`（load 或 error） | 立即发 P1 | 屏幕上那页已可上屏，槽位可以给下一张 |
| 挂载后 1500ms 仍未见当前页 settled | 强制发 P1 | 兜住"当前页命中缓存秒开"（永远不会再触发 settled 回调竞争）与"当前页已失败"两种边界 |
| 翻页落定后 | **等 200ms** 再重算窗口 | 不让预取和刚落地的这一页抢带宽；200ms 介于 `duration-fast`(150) 与 `duration-normal`(240) 之间，够浏览器把新页请求发出去 |
| 浏览器空闲 | `requestIdleCallback(timeout: 1000)` 发 P3 | **Safari 不支持 rIC**，必须有 `setTimeout(600)` 回退（iOS 是主力端，不能漏） |
| **TTS 播放中** | 网络预取**继续**（并发限 1，不发 P2/P3）；但**邻页位图不 swap 进视图** | 真正的风险不是抢带宽（`speechSynthesis` 多为本地合成），而是逐字高亮每字符一次的重渲染 + 一张 1024² 位图上屏的绘制叠一起 → `onboundary` 回调抖动、高亮跳字。下载在后台不占主线程，解码上屏才占 |
| TTS 播放中用户**手动**翻页 | 照常立即 swap，不延迟 | 用户已经在看这一页了，视觉连续性优先于音频连续性；且此时本来就会触发 250ms 的 TTS 重启（`TTS_RESTART_DEBOUNCE_MS`），是重同步时刻而非稳态 |
| 抽屉/视频面板打开（`dialogOpenRef`） | 预取继续，不额外处理 | 阅读页仍可见，无冲突 |
| 页面 `visibilitychange` → hidden | 暂停一切预取 | 后台标签页不该花用户流量 |

### 3.3 并发与抢占

**硬上限 2 路，但 P0 在飞时降为 1 路。**

推导（4Mbps = 500KB/s，HTTP/2 单连接下多流近似均分带宽，现网 HTTP/2 优先级基本未实现）：

| 在飞路数 | 单张 110KB 的完成时间 | 是否覆盖移动 slide(240ms) |
|---|---|---|
| 1 | 220ms | ✅ |
| 2 | ≈440ms | ❌（超 240ms）但仍覆盖桌面 leaf(560ms) |
| 3 | ≈660ms | ❌ 桌面 leaf 也开始危险 |

结论：**当前页独占带宽时 1 路**（220ms，安全覆盖 slide）；当前页已完成后 2 路并行预取（440ms 双双到位，此时已无人在等）。**3 路在任何条件下都不允许。**

**抢占规则**（目标页从 P1 升为 P0 时）：

- **不 abort 已在进行的那一路**——`+1` 变成当前页时，正在下载的就是屏幕上要的那张图，abort 等于白扔字节。
- **abort 掉 P2/P3 那一路**：`img.src = ''`（`HTMLImageElement` 没有 `AbortController`，只能靠清 src 取消；清完把引用置 null 让 GC 回收）。
- `saveData` / `minimal` 下并发上限 0：连当前页之外的一个字节都不许发。

### 3.4 完整判定表（工程照此实现）

> 判定顺序自上而下，**先命中先生效**。`P(x)` = 页 x 的图片请求。

| # | 如果 | 则 |
|---|---|---|
| 1 | `quality === 'minimal'` | 只发 P0；除当前页外零图片请求；不发 P1/P2/P3 |
| 2 | `quality === 'reduced'` | P0 结束后只发 P1（并发 1，串行）；P1 结束后发 P2；**永不发 P3** |
| 3 | `saveData === true` 且用户未手动翻页过 | 同 #1，且占位文案直接带"省流量模式"说明 |
| 4 | 当前页 P0 在飞 | 并发上限 1；已有预取（P2/P3）abort |
| 5 | 当前页 P0 settled | 立刻发 P1（并发上限恢复 2） |
| 6 | 挂载后 1500ms 且 P0 未 settled | 强制发 P1（不 abort P0，此时 P0 可能已卡死） |
| 7 | P1 settled | 发 P2（`-1`） |
| 8 | P1 与 P2 都 settled，且处于 idle 窗口 | 发 P3（`+2`） |
| 9 | 页 x 不存在（x<0 或 x>totalPages-1） | 跳过，不发请求（封面页 N=0 时无 `-1`） |
| 10 | 页 x 已 `decoded`（在 `decodedCache` 中） | 跳过，不发请求 |
| 11 | 页 x 上一轮刚失败过（`failedAt` 在 10s 内） | 跳过，不发请求（避免失败风暴） |
| 12 | `skimMode` 为真 | 窗口收为 `{+1}`，并发 1，abort P2/P3，不发 P3 |
| 13 | `isFlippingRef.current` 为真（翻页动画中） | 不发新预取；已在进行的不 abort（正在飞的很可能就是目标页） |
| 14 | 距上次落定 < 200ms | 不发新预取，200ms 后重算 |
| 15 | `document.visibilityState === 'hidden'` | 暂停一切预取与重试计时 |
| 16 | TTS `isPlaying` 且翻页来源为 `auto` | 不发新预取；P0 照常 |
| 17 | 图片 URL 为空（`getSceneImageUrl` 返回 `''`） | 不发请求；直接渲染"暂无插图"占位，不进加载态 |
| 18 | 用户点了某一页点阵/缩略图/拖条跳转（非相邻） | 取消全部预取，只发目标页 P0；落定后按 #5 重启 |
| 19 | 卸载 / 路由离开 | abort 全部在飞的预取（`img.src=''`），清所有定时器 |
| 20 | 当前页是封面（`currentPage === 0`） | P0 = 墙的 6 张缩略图（`thumb` 档，浏览器 lazy 自管）；**P1 = 第 1 页 `reader` 档大图**；不预取第 2 页及以后（见 §3.6.3） |
| 21 | `scene.imageBlob` 存在 | 走 `URL.createObjectURL`，**不参与档位与预取**（见 §3.6.3 末段） |

### 3.5 预取失败：不重试

| 失败类型 | 预取（P1/P2/P3） | 当前页（P0） |
|---|---|---|
| `net::ERR_*` / 连接重置 | 静默放弃，记 `failedAt` | 自动重试 1 次，退避 800ms |
| HTTP 5xx | 静默放弃，记 `failedAt` | 自动重试 1 次，退避 800ms |
| HTTP 404 / 4xx | 静默放弃，**永久**不重试 | 立即失败态，**不重试**（404 重试没有意义） |
| 超时 6000ms | 静默放弃，记 `failedAt` | 算 1 次失败，进入重试 |
| `decode()` reject | 静默放弃（图字节已进缓存，下次渲染仍可用） | 降级为直接 swap `<img src>`，不显示失败态 |

- **预取不重试的理由**：用户从未看见过这张图，为不可见的工作重试是纯流量泄漏（尤其弱网按流量计费场景）。用户翻到该页时自然进入 P0 路径，自动获得可见的重试策略——**"看不见的工作不重试，看得见的工作重试"**是这条规则的全部内容。
- **`failedAt` 窗口 10s**：防止 `visibilitychange`/`connection change`/窗口 resize 等重算事件把同一个失败 URL 反复打。
- **重试上限总计 2 次尝试**（1 初 + 1 重试），退避固定 800ms，**不做指数退避**（就一次重试，指数退避没有第二项可退）。
- **超时取 6000ms** 的理由：2g（≈250kbps）下 768 档 ≈70KB，需 2.2s，6s 给了 2.7 倍余量；再长会让弱网用户对着"正在画这一页…"发呆。

### 3.6 封面页（page 0）—— 缩略图墙的加载策略

封面页与场景页的加载模型**完全不同**，不能套用同一套规则。它同时是"内容页"和"导航页"。

#### 3.6.1 档位：按格宽取档，**不按 DPR**

| 断点 | 格宽 | 取档 | 理由 |
|---|---|---|---|
| <640（2 列） | 157px | **320w** | 157×DPR2=314 ≤320，DPR3 时略欠采样，缩略图可接受 |
| ≥640（3 列） | 168–253px | **480w** | 253×DPR1.9=480 |
| 任何断点 | — | **永不出 768 / 1024** | 见下 |

**为什么缩略图墙不按 DPR 升档**：墙是 6 张，任何升档都乘以 6。480→1024 是 6 倍字节换"缩略图上肉眼看不出"的锐度。而且格子本身是 `object-cover` 在 `aspect-[4/3]` 框里、`rounded-inner` 小尺寸，噪声与锐度在这个尺寸下不可辨。**这是全站唯一一处「放弃 DPR 对齐」的展示位，需要显式写进规范，否则下一轮会有人按 DPR 公式统一改掉。**

#### 3.6.2 加载策略：**逐格独立淡入，绝不 `all-or-nothing`**

| 项 | 规定 |
|---|---|
| 墙出现时机 | **立即**（与封面标题同帧），不等任何图片 |
| 骨架 | 沿用现有 `bg-[var(--brand-strong-soft)]`（`BookViewer.tsx:987` 已有），恒定存在 |
| 图片 | 每格独立 `loading="lazy" decoding="async"`，到位后 **240ms 淡入**（`duration-normal ease-enter`），**不整墙等齐** |
| 单格失败 | 该格停在骨架底 + 保留标题文字，**不显示错误标记**（缩略图失败不影响导航，用户点进去后由 P0 路径处理）。**不发 `role="alert"`** |
| 并发控制 | **不自建**。总量仅 84–150KB，交给浏览器原生 `lazy`（<640 时 2 列 = 仅 2 行在首屏，lazy 有效） |

**否决 `all-or-nothing`（等全部就绪再显示整墙）的三条理由**：

1. **最慢那张决定整墙时间**，且 6 张里任意一张失败 → 整墙永不出现。收益（视觉整齐）远小于风险（整块功能消失）。
2. **墙的可点性不依赖图片**。每格下方已有 `<span>{s.title}</span>` 文本（`BookViewer.tsx:1001`），并且 `aria-label` 是完整的 `第 N 幕：标题，打开`。**所以"图未到位的格子"不是"无名可点目标"** —— 它有名、有标签、有边界。这是本节能直接选"不等"的**无障碍依据**，不只是性能依据。
3. 逐格淡入的**节奏噪声**在 6 格、总时长 <500ms 的情况下几乎不可见；而 all-or-nothing 会呈现"一片空白突然整墙弹出"，反而更像"页面卡了一下"。

#### 3.6.3 封面页也是预取起点

封面（page 0）上，P0 集合是墙的 6 张缩略图，**P1 是第 1 页的阅读档大图（1024w）**：

| 优先级 | 对象 | 理由 |
|---|---|---|
| P0 | 墙的 6 张缩略图 | 用户此刻要看的东西 |
| P1 | 第 1 页 1024w | **封面 → 场景页是必然的下一步**；且"下一页"按钮、TTS 起始、点第 1 格三条路径都指向它。这一发直接决定 §8 指标 2（第 1 页 decoded ≤2.5s）能否达成 |
| — | 不预取第 2 页及以后 | 用户可能点任意一格跳走，猜错就是纯浪费 |

**用户点某一格 `jumpTo(i+1)` 时**：目标页升为 P0，**abort 封面页的 P1（第 1 页）**——如果点的正是第 1 格则不 abort（它就是要的那张）。

**触发顺序（不可颠倒，见 §11 R13）**：P1（第 1 页 1024w）**必须等墙的第 1 行（2 格）`settled` 之后才发**。否则在 4Mbps 上 6×18KB 的缩略图会和 110KB 的正文图均分带宽，把 M1 的"首格有图 ≤2.2s"挤成 3s+。优先级不是抽象的序号，是**先后顺序**。

**`scene.imageBlob` 例外**：`getSceneImageUrl()`（`BookViewer.tsx:327`）对 `imageBlob` 返回 `URL.createObjectURL()` 的本地地址，**这类图既不参与档位也不参与预取**（内存图，零网络成本，`decode()` 仍可做但无意义）。规范里所有"档位/预取/字节预算"规则只作用于走网络路径的 `imageUrl`。

## 4. 产出 2：翻页时机的取舍 —— A / B 裁决

### 4.1 裁决

> **否决 A「等图到位再翻」，采用 B「立即翻 + 占位填充」。**
> **等待阈值为 0ms —— 翻页动效在任何情况下都不等待图片。**

但需要把 B 拆成两条路径，因为它们在体感上是两回事：

```
用户翻页意图（按钮 / 手势 / 键盘 / 点阵 / 拖条 / TTS 自动推进）
        │
        ├─ isFlippingRef || 距上次落定 < FLIP_COOLDOWN_MS(300) ──→ 丢弃（现状逻辑，不改）
        │
        └─ 目标页 P
             │
             ├─ P 已在 decodedCache ──→ 【B0 命中路径】立即启动动画
             │                          动画期间旧页覆盖，用户无感
             │
             └─ 未命中 ─────────────→ 【B1 占位路径】立即启动动画
                                        + 占位填充（见 4.4）
                                        + 并发发起 P0 请求（fetchPriority=high）
```

**B0 是常态，B1 是异常。** 规范的验收目标就是让 B1 的占比尽可能低（见 §8 指标 3），但**B1 的存在是设计的一部分，不是失败的标志**。

### 4.2 否决 A 的四条理由

1. **A 的最坏情况无界，所以 A 必然退化成"B + 一段延迟"。** 3g 下 768 档要 2.2s、2g 下要 3.5s，任何"等到解码完成"的实现都必须带一个放弃阈值；一旦有了阈值，A 就等于"先白等 N 毫秒再走 B"。**在 N 毫秒里，A 的体验严格劣于 B，在 N 毫秒后 A 与 B 完全等价。** A 不存在任何胜出的子情形。
2. **A 的失败是静默的，B 的失败是可解释的。** A 让"点了没反应"——现有代码 `goToPage` 里 `if (isFlippingRef.current) return // 丢弃连点，不排队` 已经表明团队选择了"宁可丢弃也不排队"，因为排队会让点击落进死区。在已有 300ms 冷却之上再加一段无反馈等待，用户（尤其儿童）只会重复点按，然后判定"坏了"。
3. **TTS 自动推进已经强制了 B。** `startSceneReading` 在旁白播完时立即 `advanceRef.current(nextPage)`，新页的语音**已经开始**。此时若等图，会出现"声音在念第 4 幕，画面还停在第 3 幕"——这比空白更糟。既然 auto 路径必须走 B，再为 manual 单独维护一条 A 路径就是双份状态机换不到一致体感。
4. **动画本身就是天然的等待窗口，A 在重复利用它。** 桌面 leaf 560ms、移动 slide 240ms 内，旧页仍在覆盖画面。只要图片在这段时间内到位，用户**完全看不到空白**。这正是 B 想要的效果，而这不需要任何"等待逻辑"——它是免费的。

### 4.3 决策矩阵：来源 × 路径

| 翻页来源 | 允许 A？ | 走 B0/B1 | 额外规则 |
|---|---|---|---|
| 按钮 / 手势 / 键盘（manual） | ❌ | B0 → B1 | 正常 |
| 点阵 / 拖条 / 缩略图（跨页跳跃） | ❌ | B0 → B1 | 跨页跳转时 `kind='fade'`，动画只有 240ms，遮蔽最弱 → 必须**同时**把目标页设为 P0 并 abort 全部预取 |
| TTS 自动推进（auto） | ❌ **绝对禁止** | B1 | 不播报（现状已如此）；不停朗读；图未到位不影响语音 |
| `prefersReducedMotion()` | — | 无动画直接切页 | 遮蔽为 0，**100% 依赖预取命中**；这是 reduced-motion 用户唯一需要单独关注的场景 |

> **给工程的提醒**：reduced-motion 下 `goToPage` 直接 `setPage` 无动画（`globals.css:152` / `:161` 也把 `.page-layer` 的 transition 关了），所以"动画遮蔽"这一层保险不存在。这类用户的指标要按"命中率"单独看（§8 指标 3 的括号说明）。

### 4.4 阈值表

| 判定 | 阈值 | 说明 |
|---|---|---|
| 翻页动效启动前等待 | **0ms** | 不等待 |
| 图在动画结束前到位 → 用户无感 | 移动 ≤240ms / 桌面 ≤560ms / 跨页 fade ≤240ms | 4G 下 1024w WebP ≈220ms，**恰好落在移动 slide 窗口内**——这是格式修复带来的核心收益 |
| 动画结束后仅显示渐变底（无扫光） | 0–300ms | 与 `duration-fast` 同档；此区间**不显示任何文字与动效**，避免 220ms 的加载闪一下 |
| 显示扫光 `.progress-sheen` | ≥300ms | 见 §4.6 |
| 显示「正在画这一页…」 | ≥1200ms | 4G 正常路径永远到不了，出现即代表"这次慢了" |
| 显示「网络有点慢」+ 重试按钮 | ≥5000ms | 允许用户自救，不等自动重试走完 |
| 判定失败（`role="alert"`） | ≥12.8s（2×6s 超时 + 0.8s 退避）或 4xx 立即 | 最坏 13s 内必须给出确定态 |

### 4.5 连翻降级：`skimMode`

**进入条件**：2000ms 滚动窗口内 ≥3 次成功落定（`finalizeFlip`）的翻页。
（`FLIP_COOLDOWN_MS=300` 决定理论最快 ~3.3 次/秒，3 次/2s 是"孩子在快速浏览"的可靠信号）

**`skimMode` 下的行为**：

| 项 | 行为 |
|---|---|
| 预取窗口 | 收为 `{+1}`，并发 1，**abort P2/P3** |
| 图片请求 | 已滑过的页不回填（不 abort 正在飞的，但不再发起新的） |
| 占位视觉 | **不显示扫光**（快速翻页时扫光会变成一片闪烁噪声），只留渐变底 + 「正在画这一页…」 |
| 失败态 | **不显示**（避免快速翻页时 `alert` 连发打断读屏）。失败判定推迟到"停留"之后 |
| `aria-live` 播报 | **300ms 防抖，只播最后一页**（见 §7.2，这是本轮必须修的一个既有缺陷） |

**退出条件**：连续 800ms 无翻页落定，**或** 当前页图片 `settled`。退出后立刻按 §3.4 恢复正常窗口。

**为什么不做 `skimMode` 降档（快速翻页时用 480w，停下再升 1024）**：
换格式后 6 页合计 ≈660KB，全量预取也就 660KB。为省这 660KB 引入"降档 + 停留后升档"两条额外请求路径，会让停下那一页必然发生二次下载与可见的清晰度跳变（480→1024 是锐度变化，比缩略图→全图更刺眼，因为尺寸没变）。**成本收益不成立，砍掉。**

### 4.6 占位态的视觉与播报

**视觉（三态，全部复用既有 token，零新动画）**

```
┌───────────────────────────┐  ← 容器即现状：
│                           │     aspect-[4/3] + bg-gradient-to-br
│      （渐变底，始终存在）    │     from-[var(--brand-strong-soft)] to-primary/25
│                           │     图片容器**本来**就有这个底，所以
│     [ 扫光层 300ms 起 ]    │     「占位出现」不会产生任何颜色跳跃
│                           │
│    正在画这一页…           │  ← 12.5px / var(--text-muted) 4.84:1 ✅AA
└───────────────────────────┘     1200ms 起，animate-fade-in 240ms 入场
```

| 元素 | 实现 | 依据 |
|---|---|---|
| 底 | **复用现有** `bg-gradient-to-br from-[var(--brand-strong-soft)] to-primary/25` | `renderSceneSingle:824` 已有；不改动 = 零视觉回归。**桌面双页的图框底是 `bg-white/40`（`renderSceneSpread:894`），而渐变在左侧大面板上（:886）**——桌面占位只需沿用 `bg-white/40` 即可，不要为了"统一"把双页图框改成渐变，那会破坏左图右文的层次 |
| 扫光 | `div.progress-sheen`（**不要用 `animate-sheen`**） | `.progress-sheen` 同时出现在 `globals.css` 两条 reduced-motion 停用列表（L148/L157），会停在静态渐变；裸用 `animate-sheen` 依赖全局 `animation-duration:.001ms` 兜底，停在一个 1ms 抖动后的随机帧 |
| 文案 | `正在画这一页…`，`text-[12.5px] text-[var(--text-muted)]` | 4.84:1 ≥ 4.5:1 ✅；12.5px 与全站辅助文案同档 |
| 位图淡入 | `transition-opacity duration-normal ease-enter`（240ms） | 与移动 slide 的 240ms 同档 → 图在 slide 结束时开始淡入，视觉连续 |
| **禁止** | `animate-pulse` 做图片占位 | 2s 呼吸在 366×274 的大色块上像"内容在闪"，且 pulse 的节奏（2s）与全站 loading 语言（1.4s sheen）不一致 |
| **禁止** | 骨架条（3 条灰条） | 图片不是文本，灰条会暗示"这里是文字"；且 `BookSkeleton` 已经用了骨架条，两处骨架语言不同会互相打脸 |

**读屏播报**：**全部走 `BookViewer.tsx:1125` 那一个 `aria-live="polite"` 区域，不新增 live region。**

| 时刻 | 播报内容 | 规则 |
|---|---|---|
| 落定时图片未到位 | `describePage(N)` + `，图片还在加载` | **合并进同一次 announcement**（一次写入，不是两次），避免两个 utterance 排队 |
| 落定时图片已到位 | 仅 `describePage(N)`（现状） | 不额外提"图片已加载"，那是噪声 |
| 停留期间图片到位 | `第 N 页的图片已加载` | **条件**：① 用户仍在该页 ② 该页只播一次 ③ `!isPlaying`（朗读中不播，与既有"自动推进不播报"一致）④ `!dialogOpenRef.current` |
| 占位容器本身 | `aria-hidden="true"` | 装饰性，状态由 live region 承载 |
| 失败 | 容器内 `role="alert"`，文案 `这一页的画没加载出来。可以重试，也可以继续听朗读` | 仅当**当前可见页**失败；非可见页不持有失败态（翻到才评估），避免后台页用 alert 打断 |

**为什么"图片到位"要播报**：读屏用户从"图片还在加载"之后就没有下文了，会无法判断要不要等。补一条"已加载"闭合这个状态。但**必须只在用户还在该页时才播**，否则连翻 5 页会得到 5 条延迟到达的"第 N 页图片已加载"，全部无意义。

## 5. 产出 3：弱网与省流降级

### 5.1 降级开关清单（工程按此实现，7 个开关）

| # | 开关 | 触发条件 | 效果 |
|---|---|---|---|
| S1 | `prefetchEnabled` | `quality !== 'minimal'` | `false` → 除当前页外零图片请求 |
| S2 | `prefetchConcurrency` | `minimal:0` / `reduced:1` / `full:2`（P0 在飞时全部 −1，下限 0） | 见 §3.3 |
| S3 | `prefetchWindow` | `minimal:[]` / `reduced:[+1,-1]`（串行）/ `full:[+1,-1,+2]` | 见 §3.1 |
| S4 | `quality`（档位） | 阅读页：`minimal`/`reduced` → 768，`full` → 1024。**缩略图墙不受 quality 影响，一律 <640 取 320 / ≥640 取 480（§3.6.1）** | 交给 `pickImageTier()` |
| S5 | `sheenEnabled` | `minimal` 时为 `false` | 省合成 + 省电；占位只留渐变底与文案 |
| S6 | `prefetchRetry` | 恒为 `false` | 见 §3.5，与连接质量无关 |
| S7 | `failFastOnSaveData` | `saveData === true` | 超时从 6s 缩到 **3s**（省流用户更希望尽快看到"要不要继续等"的按钮，而不是替他们默默耗流量） |

**不做的降级**（明确写下来，避免下一轮被重新提议）：

- ❌ **降级为「点击加载图片」**。绘本的核心是图，把图变成一次额外点击等于把"翻页"变成"翻页 + 加载"，两步操作换不到体感收益——尤其是在 768 档只有 70KB 的前提下。
- ❌ **关闭翻页动画以省 CPU**。动画不省带宽，砍掉动画会让遮蔽窗口消失（见 §4.3 的 reduced-motion 注），反而更容易看到空白。
- ❌ **把 TTS 降级/关闭**。旁白是文本，与图片加载无关；弱网下"能听"恰恰是最有价值的降级路径（见 §5.3）。

### 5.2 何时放弃预取、保当前页

四条触发，任一命中即放弃（**当前页永远赢**）：

1. 任意 P0 请求发起 → abort 所有 P2/P3（P1 若恰好是新的当前页则保留）。
2. 当前页 P0 在飞期间 → **不发任何预取**（并发已压到 1，全部给它）；落定后 200ms 内也不发新预取，200ms 时重算窗口（此时 P0 若仍在飞，结果就是"继续不发"）。
3. `skimMode` → 窗口收为 `{+1}`，并发 1。
4. `quality === 'minimal'` 或 `visibilityState === 'hidden'` → 全部停止。

### 5.3 图片加载失败的用户可见处理

```
┌──────────────────────────────┐
│                              │
│            🖼️               │   ← aria-hidden
│   这一页的画没加载出来        │   ← 15px / var(--text-ink) 12.56:1
│   可以再试一次，也可以继续听朗读 │   ← 12.5px / var(--text-body) 7.88:1
│                              │
│      ┌──────────────┐        │
│      │  🔄 重试      │        │   ← min-h-11（44px 本体）
│      └──────────────┘        │
└──────────────────────────────┘
```

| 项 | 规定 |
|---|---|
| **重试按钮尺寸** | `min-h-11`（44px 本体高度），横向由 `px-5` 撑到 ≥90px。**禁止套 `.hit-44`** —— 依据 `globals.css:188` 约束 3：宽而矮的元件禁止套热区档，热区是等比撑到 44×44，纵向会越界压到相邻元素。这里本体已经是 44 高，热区没有存在意义。 |
| **按钮文案** | `重试`（两个动作都要能读出来：`重试` 是主，`继续听朗读` 是既有的朗读按钮，不新增） |
| **失败文案** | 不用"加载失败 / Error / 网络异常"这类技术语。用「这一页的画没加载出来」——描述现象，不描述机制。副文案必须给出**第二条出路**（继续听朗读），否则家长会以为整页都废了 |
| **是否影响 TTS** | **完全不影响，这是硬要求。** narration 是纯文本，`useTTS` 不依赖任何图片资源。失败态的容器**不得**包裹朗读按钮或用 `pointer-events-none` 遮住它。TTS 的失败只有它自己的 `role="alert"`（`ttsError`，`BookViewer:1145`） |
| **是否阻塞翻页** | 不阻塞。翻页按钮/手势/键盘照常，失败态只占图片框 |
| **失败态布局** | 必须**填满** `aspect-[4/3]` 的框、不改变框高（`min-h-[180px]` 是下限，180px 内要放得下图标+两行文案+44px 按钮 ≈ 130px，OK）。失败态把图片框撑高 = CLS，禁止 |
| **重试后的状态** | 回到占位态并**重置计时器**（300ms 扫光 / 1200ms 文案重新走一遍），不能直接跳回"正在画这一页…"满 5s 的旧进度 |
| **重试被点击时** | 按钮 `aria-busy="true"` + `disabled`，文案变 `重试中…`；不新增 live 播报（避免与 1200ms 那条重复） |

## 6. 产出 4：加载反馈阈值

### 6.1 阈值表（统一口径）

**设计原则**：**加载态只在「已存在的底」不足以解释等待时才出现。**
图片容器的渐变底是布局的一部分、永远在，所以"空白闪烁"这个问题在图片区根本不存在——阈值管的是**文字与动效**什么时候加，而不是占位块什么时候出现。

| 经过时间 | 视觉 | 动效 | 播报 | 说明 |
|---|---|---|---|---|
| 0–300ms | 渐变底 | 无 | 落定时那一条（含"图片还在加载"） | 4G 下 220ms 就到位，**任何反馈都会变成闪一下** |
| 300–1200ms | 渐变底 + `.progress-sheen` | sheen 1.4s linear infinite | 无 | 无文字，靠运动传达"在动" |
| 1200ms–5s | + `正在画这一页…` | `animate-fade-in` 240ms 入场，sheen 继续 | 无 | 1200ms 是"这次真的慢了"的信号 |
| 5s–12.8s | + `网络有点慢，可以先点朗读` + `重试` 按钮 | sheen 继续 | 无 | **把自救手段提前**，不等自动重试走完 |
| ≥12.8s 或 4xx | 失败态（§5.3） | `animate-fade-up` 320ms | `role="alert"` 一次 | 最坏 13s 内必须有确定态 |
| 修复后图到位 | 位图 `opacity 0→1` 240ms 淡入，占位同时淡出 | `transition-opacity duration-normal ease-enter` | 「第 N 页的图片已加载」（条件见 §4.6） | 不闪白：位图叠在渐变底之上淡入 |

**例外（唯一的）**：`app/read/[id]/page.tsx` 的 `BookSkeleton` 与 `app/loading.tsx` **立即显示，不加 300ms 延迟**。
理由：它们替换的是**整页**，在此之前屏幕是全白/上一个路由的画面；立即给出骨架严格优于空白。这两处的 `animate-pulse` 保留（全局 reduced-motion 规则已将其时长压到 .001ms + 1 次迭代，合规）。

### 6.2 「首屏可用」标准（可验收）

> **标准：分三级里程碑，逐级可用，不等全部 6 页。**

这条标准的关键洞察有两条：
1. **阅读页从来不是"整页空白"**——`renderSceneSingle` 的标题、场景描述、旁白面板、朗读按钮全部不依赖图片。
2. **封面页也不是"整页空白"**——缩略图墙的 6 个格子各自带标题文字和 `aria-label`，**不依赖图片即可点**。

所以"首屏可用"按**文字与可点性**定义，图片各自有独立的第二条指标。

#### M1 — 封面可用（进阅读页后第一屏）

| 指标 | 门槛 @4G | 方法 |
|---|---|---|
| 封面标题 + 释义**可读** | **≤1.2s** | 首个 `h1`（`BookViewer.tsx:951`）文字可见 |
| 缩略图墙**可点**（不等图，只要求 6 格按钮渲染完成） | **≤1.5s** | `button[aria-label^="第"]` 计数 = 6 且可命中 |
| 缩略图墙**首格有图** | ≤2.2s | 首个格内 `<img>` 的 `load` |
| 缩略图墙 **6 格全部有图**（**非门槛项，仅观测**） | ≤3.0s | 第 6 个格内 `<img>` 的 `load` |

> 为什么"可点"要早于"有图"：格内有标题文字 + 完整 `aria-label`，用户（含读屏用户）能凭文字识别目标。图是辅助识别，不是识别前提。若强行让"可点"等待"有图"，等于把 M1 从 1.5s 拉到 3.0s，收益只有"更好看的格子"。

#### M2 — 第 1 页可读（用户翻到第 1 页时）

| 指标 | 门槛 @4G | 方法 |
|---|---|---|
| 第 1 页文字**可读** + **朗读可启**（按钮可点且立即出声） | **≤1.8s**（从进阅读页起算，含封面停留） | `speechSynthesis` 的 `onstart` |
| 第 1 页插图 **decoded** | **≤2.5s**（从进阅读页起算） | `<img>` `load` → `decode()` resolve |
| 第 1 页插图**可见**（非占位） | ≤2.5s | 同上一行（decoded 后同帧 swap） |

> 第 1 页能在 2.5s 内 decoded，**依赖 §3.6.3 的「封面页即预取第 1 页 1024w」**。若不做这条预取，用户从封面点第 1 格时才发请求，2.5s 不成立（要 3.0s+）。

#### M3 — 全书就绪

**不设门槛，不作为验收项。** 明确禁止任何形式的"等全部 6 页就绪再显示"。

**前置依赖（不满足则 M1/M2 不成立）**：阅读页首屏 JS（gzip）≤300KB。字体 1880KB 已由 lead 转视觉角色处理（缩到 400+700 / 自托管子集 / 中文回退系统字体，三选一），不在本规范内裁决。

## 7. 响应式与多端

### 7.1 断点与翻页形式的差异（决定了"命中率"要求不同）

| 断点 | 翻页形式 | 动画时长 | 遮蔽窗口 | 结论 |
|---|---|---|---|---|
| <768（单页） | slide 位移 | 240ms | **240ms** | 4G 下 1024w WebP ≈220ms，**刚好**在窗口内 → 命中率要求最严 |
| ≥768（双页） | 3D leaf 半页翻转 | 560ms | **560ms** | 窗口是移动的 2.3 倍，预取命中率要求可放宽 |
| 跨页跳跃（任意） | fade | 240ms | 240ms | 遮蔽等同 mobile；且跳转本身是显式意图，用户心理预期就含"要等一下" |
| reduced-motion（任意） | 无动画直接切页 | 0ms | **0ms** | 遮蔽为零，100% 依赖命中 —— 这些用户的 B0 命中率必须单独测量 |

### 7.2 播报防抖（本轮必须修的既有缺陷）

现状 `handleLanding` 在每次 manual 落定时 `setAnnouncement(describePage(toPage))`。`FLIP_COOLDOWN_MS=300` 意味着最多 **3 次/秒** 写入 `aria-live`，每次 utterance 约 1.5–2s → 读屏队列积压 6s 以上，用户听到的是"第2页第3页第4页"的残句。

**修复要求**（不新增 live region，只改写入节奏）：

- manual 落定的播报统一 **300ms 防抖**：300ms 内多次落定只播最后一次。
- 与既有 `TTS_RESTART_DEBOUNCE_MS=250` 的关系：播报防抖取 300ms（略大于 TTS 重启），避免"先播页码再被 TTS 打断"。
- `source === 'auto'` 仍然完全不播（现状正确，保持）。
- 播报内容在 `skimMode` 下可简化为 `第 N 页`（省略"共 X 页"），进一步缩短队列占用。**这是可选项，不是必须**——若工程觉得分支太多，保持完整文案 + 防抖已经足够。

### 7.3 触控与指针

- 失败态的「重试」按钮：`min-h-11`，本体 44px（见 §5.3）。
- **禁止**在图片框内叠加任何"点击图片重试"的隐式热区：图片框 366×274，点它应该是翻页手势区（`useSwipePager` 的 `planeRef`），叠一个重试热区会和横滑冲突。重试必须是显式按钮。
- `hit-44` / `hit-40` 本轮不新增使用点。若工程认为某个新元素需要，先核对 `globals.css:182–196` 的五条约束（尤其约束 4：`overflow-hidden` 祖先会裁掉 `::after`，而图片容器正是 `overflow-hidden`）。

#### 8.5.4 判定规则（脚本出口）

```
通过 ⟺ 所有 P0 行 pass === true
OBS 行只写日志，不参与通过判定
任一 P0 行 fail → 退出码 1，并打印 {id, value, threshold, selector, url} 便于定位
```

- **每条必须能输出 `{ id, priority, value, unit, threshold, pass }` 的 JSON**，脚本末尾汇总为一张表并回写到本文档附录（可选）。
- **不允许"人工看一眼觉得还行"**：本表 21 行里没有任何一行依赖主观判断。若某行在实现上确实无法机械化（例如 M-14 探针被视口裁剪），**该行必须显式输出 `unverifiable` 并计入 fail**，不允许静默跳过 —— 静默跳过是验收表失效的唯一原因。

## 11. 高风险交互与降级方案

| 风险 | 触发条件 | 后果 | 降级方案 |
|---|---|---|---|
| **R1 预取把当前页挤慢** | 并发 2 且 P0 未完成 | 首图从 220ms 变 440ms，移动端 slide 窗口保不住 | 已由 §3.3「P0 在飞时并发降为 1」消解；实现时必须按 "P0 started → abort P2/P3" 编码，不能只在计数上做文章 |
| **R2 预取 URL ≠ 渲染 URL** | 预取器自己拼路径 / 档位判定两处不一致 | 双倍下载 + 画质跳变（最隐蔽，测试难发现） | 强制走 `pickImageTier()`；验收时在 Network 面板核对「预取请求数 = 渲染请求数」（缓存命中时后者为 0） |
| **R3 iPhone 被误判为 4G** | Safari 无 `navigator.connection` | 实际弱网用 1024 档 + 2 路并发：110KB 在 400kbps 上单路 2.2s、双路约 4.4s，而正确降为 `reduced` 后是 70KB/单路 ≈1.4s —— **慢 2–3 倍，且会直接击穿 2.5s 的首图指标** | §2.1 的实测回退（第 1 页 >3s 或 <200kbps → 降 `reduced`）；**这是 iOS 唯一防线，必须实现** |
| **R4 占位层进入 3D 翻转层** | 占位渲染在 `renderPage` 之外或被 `.flip-leaf` 包含 | 桌面翻页时占位跟着纸页一起翻转，出现"纸上有空洞" | 占位必须在 `renderPage(currentPage)` 内部（即 `page-layer` 底层），不参与 `flip-leaf` 快照 |
| **R5 `aria-live` 连发** | 连翻 / 图片到位 / 失败三方同时写 | 读屏队列积压 6s+，用户听到残句 | 单 region + 300ms 防抖 + "图片到位"只在当前页且只一次（§7.2 / §4.6） |
| **R6 失败态时用户以为整页坏了** | 图失败 | 家长退出阅读 | 副文案给第二出路「可以继续听朗读」；朗读按钮保持可见可点 |

## 12. 工程契约（实现时的接口边界）

```ts
// lib/image-tiers.ts —— 全站图片 URL 的单一产地（lead 定稿）
// 对外：tierUrl / pickImageTier / TIER_SETS。组件一律不得手拼路径。
pickImageTier(opts: {
  usage: 'bookshelf' | 'thumb' | 'reader'
  dpr: number
  /** 展示位宽度（px）。'thumb' 只按它取档，不看 dpr —— 见 §3.6.1 */
  layoutWidth: number
  quality: 'full' | 'reduced' | 'minimal'
}): { width: 320 | 480 | 768 | 1024; url: string; srcset?: string }
```

取值规则（按 `usage` 分派，这是三档策略最容易写错的地方）：

| usage | 取档依据 | 结果 |
|---|---|---|
| `reader` | `quality` | `full` → 1024；`reduced`/`minimal` → 768 |
| `thumb` | **只看 `layoutWidth`**（**不看 dpr、不看 quality**） | `<640` 视口格宽 157 → 320；`≥640` 格宽 168–253 → 480 |
| `bookshelf` | `dpr` | `dpr≤1` → 320；`1<dpr≤1.5` → 480；`dpr>1.5` → 768（**永不 1024**） |

```ts
// hooks/use-prefetch.ts —— 建议签名（任务 #5 落地）
usePagePrefetch({
  pages: Array<{ page: number; url: string }>   // 由调用方用 pickImageTier 预先算好
  currentPage: number
  quality: 'full' | 'reduced' | 'minimal'
  enabled: boolean            // isPlaying / dialogOpen / visibility 的综合闸门由调用方给
  isFlipping: boolean
  onDecoded: (page: number) => void   // 写入 decodedCache 并触发重渲染（可选）
}): {
  isDecoded: (page: number) => boolean
  failedAt: (page: number) => number | null
  retry: (page: number) => void       // 供失败态按钮调用（P0 路径）
}
```

**三条实现红线**：

1. **URL 只能由 `lib/image-tiers.ts` 产出**（`tierUrl` / `pickImageTier`），组件禁止手拼路径（R2）。
2. **占位层在 `page-layer` 底层内，不进 `flip-leaf`**（R4）。
3. **`aria-live` 只有一处**（§9 第 1 项）。

**外加一条验收前置**：§8.5.2 的 3 个 `data-*` 钩子（H1/H2/H3）。不加，21 条验收里有 8 条无法机械核对，会退化成"人工看一眼"。

### 脚本口径说明（与本文判定的差异，均已对齐意图）

- 字节用 CDP `Network.loadingFinished.encodedDataLength`（含响应头），比本地服务上的
  `performance.transferSize` 稳定；`M-04a` 177KB 含封面预取第 1 页，属设计内。
- `M-03` 用翻页期间 8ms 轮询采样占位可见时长（≤16ms 记 B0）。
  不在页面生命周期里挂全局 MutationObserver：CPU4× 下它会拖慢首屏 30s，测量工具会污染被测量对象。
- `M-15/M-16/M-20/M-21` 的图片失败用 `route.abort` 且**只拦图片扩展名**——
  `book.json` 也在 `/generated/` 下，一起拦会停在错误页，产生空真通过。
- 弱网条目用 `addInitScript` 伪造 `navigator.connection`（CDP 限速不会改它）。
